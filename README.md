# Mickey's Speedway USA

**A matching decompilation of the US release of *Mickey's Speedway USA* (Nintendo 64, Rare, 2000).**
The source in this repository rebuilds the retail ROM byte for byte.

> **Bring your own ROM.** This repository contains no ROM data, extracted
> assets, or compiler binaries. You need a legally obtained US ROM with SHA-1
> `507341c0a40ca3e9a7cee969b396ee53facfb548`.

## Getting started

### Requirements

| Tool | Notes |
| :--- | :--- |
| GNU Make | invoked as `gmake`; macOS's bundled `make` is too old |
| Python 3 | `gmake setup` creates the virtual environment |
| `mips64-elf-binutils` | the cross assembler, linker and objdump |
| IDO 5.3 | the original SGI compiler, run through [ido-static-recomp](https://github.com/decompals/ido-static-recomp/releases) |

On macOS:

```sh
brew install make python3 mips64-elf-binutils
```

Place the IDO build under `tools/ido/` and the prefixed binutils under
`tools/binutils/`. If a local
[Diddy Kong Racing](https://github.com/DavidSM64/Diddy-Kong-Racing) checkout is
available, `tools/setup_toolchain.sh` copies its compatible binutils and IDO
files for you.

### Build and verify

```sh
cp /path/to/your/rom.z64 baseroms/mickey.us.z64
gmake setup                          # hash check, venv, submodules, split, git hooks
gmake -j$(sysctl -n hw.ncpu)         # build/mickey.us.z64
gmake verify                         # byte-compare against the target hash
```

`gmake verify` prints the expected SHA-1 when the rebuilt ROM is identical.

> The PAL and Japanese configuration files come from the original repository
> and have not been updated or verified.

## Working on a function

Functions that have not matched yet remain as `#pragma GLOBAL_ASM` includes.
The loop is: replace one function, build its translation unit, compare the
object, then run `gmake verify` before recording it as matched.

```sh
./mips_to_c.sh <symbol>     # first C translation with m2c
./diff.sh <symbol>          # compare target and current assembly
./diff.sh -mw <symbol>      # rebuild and watch the comparison
./generate_ctx.sh           # regenerate ctx.c for m2c
gmake verify                # prove the whole ROM still matches
```

Two things that catch newcomers:

- **Overlay addresses are reused at runtime.** Identify overlay code by
  overlay, section and offset through `config/overlays.us.json`; a virtual
  address alone is ambiguous.
- **Compiler flags vary per file.** The default is `-O2 -mips1 -32`; the
  per-file differences are listed in the root Makefile for resident code and
  [`mk/overlays.mk`](mk/overlays.mk) for overlay code, then summarised in the
  [module map](docs/modules.md). The overlay policy file is build metadata for
  matching function-sized objects; it is not the runtime overlay system.
  Runtime loading is implemented in `src/main/runlink.c` and documented in
  [the overlay architecture guide](docs/overlays.md#51-what-runs-it).

The host build has one object graph and one final linker invocation; splat
generates overlay inputs and their `mickey.us.ld` placement. The
[contributor guide](docs/CONTRIBUTING.md#overlay-build-flow) traces that path
and separates it from the Rare-lineage runtime loader. Keeping measured
per-overlay-object policy in `mk/overlays.mk` makes that one-build/one-link
graph visible in the root Makefile without changing its behavior.

When a candidate compiles to the right shape but the register or stack
allocation still differs, `tools/permute_batch.py` runs
[decomp-permuter](https://github.com/simonlindholm/decomp-permuter) against
the project's real per-file build recipe; see
[docs/permute-batch.md](docs/permute-batch.md).

## Project checks

| Command | Purpose |
| :--- | :--- |
| `gmake verify` | Rebuild the US ROM and compare it with the target hash |
| `gmake cleanroom` | Reject tracked ROM data and prohibited file types |
| `gmake check-docs` | Recompute the numeric claims in the documentation |
| `gmake check-scoreboard` | Compare the Progress section above with the current build |
| `gmake overlay-atlas` | Check the overlay map and generated YAML segments |
| `gmake overlay-donors` | Check the recorded overlay reference results |
| `gmake check-reference-builds` | Check local reference objects against the lock file |

Some checks need a local ROM or reference checkout and therefore do not run in
public CI. See [Contributing § Checks](docs/CONTRIBUTING.md#checks) for the
full list.

## Contributing

Read [Contributing](docs/CONTRIBUTING.md) and the
[clean-room policy](docs/CLEANROOM.md) before changing source, and do not
bypass the git hooks. A function counts as **matched** only when the
unmodified compiler output links to the correct location and matches every
owned byte — no post-compile edits to instruction words, ever.
