// GAME CODE BYTE-IDENTICAL TO THE DIDDY KONG RACING BUILD
//
// Mickey's Speedway USA is not merely DKR-*lineage*: parts of DKR's own game
// code are present in this ROM instruction for instruction. Every name in this
// block was adopted because the bytes at that address are byte-identical --
// under relocation masking, exactly as for the libultra corridor -- to the
// same-named symbol in the DKR decompilation's *built* game objects
// (`build/src/**/*.o`, not `build/libultra`). Reproduce with:
//
//   tools/find_known_objects.py <dkr>/build/src --start 0x1000 --end 0x86640
//
// and, for the ROM-wide occurrence count that each row below cites, the same
// command with `--start 0x1000 --end 0x2000000 --max-occurrences 60`.
//
// Per-row evidence is `masked=M/W`: W instruction words compared, M of them
// masked because the reference object's own relocation records say the linker
// patches them. Everything else matched verbatim. Every row below is ALSO
// unique across the whole 32MB image (`romocc=1`), which is the property Task
// B's window-scoped `occ` column could not establish -- see the workbench log.
//
// ADOPTION THRESHOLD, applied mechanically: at least 6 unmasked words, plus
// ROM-wide uniqueness, plus exactly one candidate name for those bytes. Rows
// that failed it are listed in the Task D report rather than silently dropped;
// the notable rejects are `debug_text_origin` (1 unmasked word of 9),
// `input_assign_players` (4 of 9), `bgdraw_primcolour` (4 of 10),
// `tex_enable_modes` (5 of 7) and everything at ROM 0x17F8, 0x1B74, 0x27A0,
// 0x27C4, 0x545C, 0x8D18, 0x1BE90, 0x29B98, 0x2CB44, 0x2D39C and 0x35024,
// where several *different* DKR functions compile to the same bytes and byte
// comparison therefore cannot say which one this is.
//
// WHAT THIS TIER DOES AND DOES NOT ESTABLISH. It establishes that the routine
// at this address is the same routine DKR compiled, and that is a hard,
// reproducible fact. It does NOT establish that DKR's *name* describes what
// Mickey uses it for -- `weather_clip_planes` and `audspat_jingle_off` are
// DKR's names for DKR's game, carried here because renaming shared code would
// hide the sharing. See docs/CLEANROOM.md: only DKR's compiled bytes and its
// symbol and relocation tables were read, never its source.
// ---------------------------------------------------------------------------

// --- extension: four more linker functions, from Mickey's own call graph ----
//
// These are NOT byte-identity. Each is read out of Mickey's disassembly and
// then matched to a JFG function by role; the disassembly evidence is stated
// per name and is what should be attacked if one of these is wrong.
//
// TrapDanglingJump (0x800333A0). Decisive on Mickey's code alone. It saves
// a0-a3, f12-f15, v0 and v1 -- every argument register of an interrupted call
// -- computes `addiu t5, ra, -8` (the address of the `jal` that reached it),
// searches an 8-byte-stride table for that address, loads the missing overlay,
// recomputes the real target and `jr t8`s to it with the arguments restored.
// A trampoline that resolves its own caller is exactly the routine JFG
// documents under this name, and nothing else in this ROM has that shape.
//
// runlinkDownloadCode (0x80031C78). The argument TrapDanglingJump passes it is
// `romTableEntry >> 20`, i.e. an overlay number (ROM 0x34090-0x34098); it
// returns zero/non-zero, and TrapDanglingJump falls through to a null return
// when it is zero. It calls ProcessRelocationEntry in a loop and finishes with
// osInvalICache. Loads an overlay and relocates it: JFG's signature is
// `s32 runlinkDownloadCode(s32 overlayIndex)`.
//
// runlinkGetAddressInfo (0x800331E4). Four arguments: an address, two pointers
// it zeroes on entry, and an OPTIONAL fourth it only writes when non-NULL
// (`beqz t8` at 0x33E28). It walks the ROM table looking for the entry whose
// span contains the address, then the overlay table, and writes back
// (moduleId, offsetWithinModule), returning 1 on a hit and 0 otherwise. JFG's
// prototype is `s32 runlinkGetAddressInfo(u32 address, s32 *moduleId,
// s32 *moduleAddress, u32 **arg3)` and its diCpuReportWatchpoint calls it with
// NULL for the fourth -- which is what Mickey's own watchpoint reporter at
// 0x80046460 does too.
//
// GetSymbolName (0x800317E0). Four instructions. It is called from exactly one
// place, runlinkGetAddressInfo, with a *symbol table index* (computed as
// `(cursor - tableBase) >> 2` over the 4-byte ROM table, ROM 0x33ED0-0x33ED8),
// and its result is stored into that function's optional fourth out-parameter
// -- the symbol-name slot. Its whole body ignores the argument and returns a
// pointer to the constant string "unknown" at 0x80082410. So Mickey's retail
// build ships the lookup stubbed to its failure value, with the ROM-side
// symbol string table that JFG's version reads simply absent. The name is
// adopted for the ROLE the call site proves, and the stub is the finding.
